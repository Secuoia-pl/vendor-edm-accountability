# Baza podprogowa — szara eminencja (bez oficjalnych skrzynek)

**Rama (jedna, powtarzana):**  
> Problem nie zaczyna się w momencie ataku — zaczyna się, gdy milion ludzi jest zależnych od jednego vendora bez równoważnej odpowiedzialności.

**Zasada:** nie pitchujesz. Zostawiasz gotowiec, który ktoś zajęty sam podnosi.  
**Sukces:** fraza wraca cudzymi ustami. Nie Twoje nazwisko.

---

## 1) Kogo celować (typy, nie oficjalne maile)

Szukaj osób **z klawiaturą, bez kolejki PR**.

| Priorytet | Typ osoby | Gdzie ich znaleźć | Dlaczego |
|----------:|-----------|-------------------|----------|
| 1 | Freelancer / stały współpracownik redakcji tech-cyber | byliny „tekst dla…”, LinkedIn „Journalist”, X bio | pisze szybko, szuka kąta |
| 1 | Asystent / doradca biura poselskiego (cyfryzacja, zdrowie, administracja) | Sejmowiec, LinkedIn „asystent posła”, X | składa pytania i notatki |
| 1 | Community / social w mediach niszowych | osoby publikujące z kont redakcji | potrzebują 1 mocnego zdania |
| 2 | Junior analyst w think-tanku / izbie / stowarzyszeniu | LinkedIn 0–5 lat exp. | robi research dla starszych |
| 2 | DPO / security w mid-size (nie top bank) | grupy RODO, ISSA, lokalne CISO meetupy | mniej filtrów, szybciej testują język |
| 2 | Host małego podcastu / newslettera (1–15k) | Substack, Spotify, LinkedIn newsletter | głodni treści |
| 3 | Moderator / aktywny członek grupy branżowej | Discord/Slack/FB zamknięte | ustawia ton wątku |
| 3 | Prelegent side-eventu, nie keynote | agenda konferencji, „lightning talk” | otwarty na gotowe pytania z sali |
| 3 | Prawnik / konsultant mid-level (nie partner) | komentarze pod ustawami, LinkedIn | chce wyglądać bystro przed klientem |

### Szybki filtr „czy warto”
Pisz, jeśli osoba w ostatnim miesiącu:
- opublikowała coś o wycieku / AI Act / RODO / EDM, **albo**
- zadała pytanie w komentarzu, **albo**
- prowadzi mikrokanal bez sztabu PR.

Nie pisz do: rzeczników, marketingu, „kontakt@”, top influencerów z kolejką.

## 2) Gdzie działać (miejsca, nie skrzynki)

### Warstwa A — publiczne, ale „miękkie”
- komentarze pod postami: CERT/NASK, cyber-media, dziennikarze mid, CISO mid
- wątki LinkedIn pod artykułami o MyDr / danych / vendorach
- odpowiedzi na X **pod średnimi kontami** (nie pod viralem 2 mln)
- sekcje komentarzy przy tekstach (gdy żywe)

### Warstwa B — półzamknięte
- Discord/Slack/Telegram grup cyber, RODO, ISSA, lokalne security meetup
- grupy LinkedIn (compliance, e-zdrowie, ISMS) — komentarz, nie post-sprzedaż
- fora / społeczności konferencyjne (pre/post event)

### Warstwa C — prywatne, peer
- DM LinkedIn / X po **ich** poście (nie cold znikąd)
- krótka prośba o feedback do juniora: „czy to pytanie jest czytelne?”
- wymiana 5 bulletów z freelancerem „na deadline”

### Warstwa D — offline (najmocniejsza podprogowość)
- pytanie z sali na side panelu (1 zdanie)
- rozmowa z asystentem przy stoliku, nie z ministrem
- after: „mam jedną ramę, która się sprawdza w briefach…”

## 3) Szablony komentarzy (podprogowe)

**Reguły:** max 3–5 zdań · 1 rama · 0 linków do siebie · 0 „jestem ekspertem” · 0 CTA sprzedażowego

### K1 — dopięcie ramy
```
Najciekawsze nie jest „czy wyciekł PESEL”, tylko model:
pacjent nie wybiera systemu, a skutki ponosi przy incydencie vendora.
To zmienia pytanie z IT na odpowiedzialność łańcucha powierzeń.
```

### K2 — pytanie, które ktoś może ukraść
```
Jedno pytanie, które warto dociągnąć w tej sprawie:
jakie obowiązki ex ante powinien mieć vendor EDM działający
w skali tysięcy placówek — zanim dojdzie do kolejnego incydentu?
```

### K3 — przesunięcie osi
```
Zastrzeżenie PESEL pomaga obywatelowi.
Nie rozwiązuje jednak problemu koncentracji danych zdrowotnych
u pojedynczych dostawców. To dwa różne poziomy odpowiedzialności.
```

### K4 — „dla busy people” (bardzo kopiowalne)
```
TL;DR ramy:
atak = trigger
vendor concentration = przyczyna strukturalna
brak wyboru po stronie pacjenta = powód, dla którego to jest temat publiczny
```

### K5 — pod postem firmowym / PR
```
W komunikatach często pada „to był atak”.
Dla klientów ważniejsze jest: jaki był plan 24/72h na łańcuch powierzeń
i kto realnie prowadzi opiekę nad osobą, której dane mogły wyciec.
```

### K6 — pod tekstem regulacyjnym (AI Act / UODO / MC)
```
Przy danych zdrowotnych egzekucja „po fakcie” zawsze spóźnia się
względem skali. Sensowniejsze pytanie: jakie minimum ex ante
dla vendorów o krajowym zasięgu.
```

### K7 — ultra-krótki (X)
```
Nie „czy zhakowali”.
Tylko: kto odpowiada, gdy pacjent nie wybierał systemu.
```

## 4) Szablony DM „peer note” (nie outreach)

**Reguła:** pisz tylko po ich aktywności (post/tekst/komentarz) · max 800 znaków · zero „chcę współpracować”

### D1 — po ich poście
```
Hej [Imię] — przy Twoim wpisie o [temat] dopiąłbym jedno pytanie,
które dobrze działa w briefach:

„Kto odpowiada, gdy pacjent nie wybierał EDM, a vendor ma skalę krajową?”

Jak chcesz, podeślę 5 bulletów bez podpisu — do użycia / przerobienia.
Bez cytowania mnie.
```

### D2 — do freelancera na deadline
```
Cześć [Imię], widziałem że bierzesz [temat].
Jak masz 20 sekund: gotowa rama + 3 pytania pod rozmowę z bohaterem.
Mogę wrzucić tu w DM. Zero afiliacji.
```

### D3 — do asystenta / juniora
```
[Imię], robię krótkie notatki pod kątem „vendor accountability”
przy danych zdrowotnych. Jeśli zbierasz materiał do pytań/notatki,
mogę podesłać one-pager w punktach — do dowolnego użycia.
```

### D4 — do mid CISO / DPO (po ich komentarzu)
```
[Imię] — Twoja uwaga o [X] trafia w sedno.
U mnie w briefach sprawdza się rozróżnienie:
ochrona obywatela (PESEL) vs odpowiedzialność vendora (ex ante).
Jak chcesz, wrzucę 6 punktów pod wewnętrzne memo.
```

### D5 — „czy to czytelne?” (najmniej sprzedażowe)
```
Szybki test czytelności — 1 zdanie:
„Problem zaczyna się od zależności od vendora, nie od ataku.”
Brzmi jasno dla nie-IT, czy jeszcze za technicznie?
```

### D6 — follow-up cichy (po 3–5 dniach, tylko jeśli otworzyli/odpisali)
```
Update w 3 punktach po ostatnich doniesieniach:
1) …
2) …
3) …
Jak kąt nadal żywy — mogę dać wersję 5 zdań pod post/pytanie.
```

## 5) Artefakty do „zostawienia” (kopiowalne)

Trzymaj w notatniku i wklejaj bez brandingu:

### A) Karta 1 zdanie + 3 pytania
```
Rama: zależność od vendora > sam atak.

Pytania:
1) Jakie minimum security/incident ma vendor EDM skali krajowej?
2) Jak obywatel ma w 72h ustalić „czy ja”?
3) Co jest egzekwowalne wobec vendora, nie tylko placówki?
```

### B) Tabela 4 wiersze (do kradzieży przez social)
```
Warstwa        | Co robi                 | Czego nie robi
PESEL          | chroni osobę            | nie zmienia modelu rynku
Komunikat PR   | uspokaja narrację       | nie buduje odpowiedzialności
Kontrola UODO  | egzekwuje po fakcie     | nie zastępuje ex ante
Vendor risk    | tu jest dźwignia systemu| dziś najsłabiej opisane
```

### C) Pytanie z sali (offline)
```
Dziękuję. Krótko: czy w rekomendacjach po incydencie przewidujecie
obowiązki ex ante dla vendorów EDM o zasięgu krajowym, czy zostajemy
przy komunikacji skierowanej głównie do obywatela?
```

## 8) Antywzorce (zabijają podprogowość)

- „Jestem ekspertem, chętnie wypowiem się w materiale”  
- link do LinkedIn / oferty w pierwszym kontakcie  
- ten sam komentarz copy-paste pod 20 postami w godzinę  
- spór ideologiczny zamiast jednej ramy  
- pisanie do rzecznika / marketingu  
- proszenie o credit  

---

## 9) Upgrade (gdy fraza zaczyna wracać)

Dopiero wtedy:
1. zaproponuj cichy retainer / white-label memo (Biznes)  
2. daj fuller brief osobie, która już użyła ramy  
3. ewentualnie 1 oficjalny mail — ale jako kontynuacja relacji, nie cold

Podprogowość najpierw buduje **język w obiegu**.  
Oficjalne kanały służą później do **spieniężenia dostępu**, nie do startu.
